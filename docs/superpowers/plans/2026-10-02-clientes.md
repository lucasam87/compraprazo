# Clientes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Implementar cadastro, busca, edição e inativação segura de clientes.

**Architecture:** Schemas Zod validam entradas no servidor; Server Actions exigem perfil ativo e usam Supabase SSR; páginas server-rendered consultam somente clientes ativos por padrão. Inativação atualiza `ativo` e nunca remove registros.

**Tech Stack:** Next.js App Router, TypeScript, React, Supabase SSR, Zod, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-02-clientes-design.md`

## Global Constraints

- Telefone é opcional; quando informado, contém somente dígitos.
- Limites são inteiros em centavos.
- Nenhum registro é apagado; inativação usa `ativo = false`.
- Toda Action valida perfil ativo no servidor e não expõe erros brutos do Supabase.
- A RLS do Supabase permanece autoridade de dados.

## Review Focus

- Telefone ausente deve ser aceito sem inserir string inválida — Task 1.
- Telefone com máscara/letras deve ser rejeitado — Task 1.
- Limite fracionário, negativo ou fora da faixa segura deve ser rejeitado — Task 1.
- Usuário sem perfil ativo não pode criar/editar/inativar — Task 2.
- Inativação deve preservar registro e ocultá-lo da lista padrão — Task 2/3.
